# 子智能体指令规范

派子智能体是一次**上下文减负**：同一件调研任务，它读全部 50 条，主轨只读 10 条。
它给的是**判断素材**，不是终局判决——最终裁决仍在主轨和用户。

模板可直接复制，替换 `{}` 占位符。字段名、编号规则、统计口径都在 `scripts/dump.py` 里定义，本文件不重复。

---

## 任务定位

子智能体和主模型做的是**同一件事：回答用户的调研问题**。区别只在样本量——它读全部 50 条，主轨只读 10 条。派它是因为内容太多、塞不进主上下文，本质是「上下文减负」，不是换一个任务。

由此推出两条，很容易写反：

- **任务目标是回答，不是审计。** 把「找错」当成它的职责，它会为了挑刺而挑刺，甚至刻意回避与主轨一致的结论。
- **输出只写增量，这是省 token 的手段，不是任务本身。** 但别为了「显得有增量」而略过重要结论——一致的照写，标「一致」即可。

## 可复制模板

```
【任务】
{用户真正想知道什么，说人话，不要抄搜索词}

主轨已看过其中 10 条，初步结论是：
{主轨结论，逐条列}

你能看到全部 50 条。你的任务是回答上面这个问题——不是做挑错练习，也不要写领域综述。
你手上样本是主轨的 5 倍，答案理应更全面，或者纠正它的偏差。

【数据】
python {dump_py} {archive}                 # 全部条目：编号/权威/站点/日期/标题/snippet
python {search_py} --replay {archive} --expand {编号} --expand-max {字数} --expand-only
不要用 Read 打开存档 JSON——里面含完整 summary，可达数百 KB，会烧光你的上下文。
第一轮只看 snippet；summary 与 content 通过上面的 --expand 单独取。

**默认不做权威过滤，你看到的就是引擎返回的全部结果**（通常是 50 条），顺序即引擎的 rerank 降序。
若主轨这次用了 `--min-authority`，dump 会按存档记录复现同一套过滤，条数会少于 50——那时的样本不是全量，报告里要注明。
`authority` 字段只当参考读：它衡量域名眼熟程度，不是内容质量。低 authority 不等于低价值。

**编号是「过滤 + 去重后」的序号**，dump、列表、--expand 三处一致，可以直接互相引用。
（只有给 dump 加 `--all` 时才变成未过滤的原始顺序，那时候编号会变。）

【输出 · 第一部分：答案】
先直接回答问题，再只写与主轨的差异，用三种标记：
  补充 —— 主轨没说但重要的
  修正 —— 主轨说错或说过头的
  一致 —— 你确认主轨对（一行即可，不展开）
不要重写完整答案：主轨读过那 10 条，重复部分对它是零信息。

【输出 · 第二部分：证据状态】
A 重复：同一内容的多条编号（同 DOI、同 URL 变体、同标题）
B 矛盾：做成三列表格，一行一条——| 谁在说什么 | 原文引句 | 条目编号 |
   例：| 该基准称最强系统成功率约 7% | "the best systems reach 7%" | 24 |
C 覆盖缺口：哪几条讲了主轨没提的重要角度，说明为什么重要
D 可疑：只写有正面证据的（无出处、自认是预测值、元数据与内容不符、明显 AI 生成模板）
E 待核：看着可疑但可能只是 snippet 被截断，写清缺什么前提

【规则】
1. 编号 = results 数组下标 + 1，必须精确
2. 每条判断标置信度：高 / 中 / 低
3. 引句用 > 原样贴出，不改写
4. 禁写"总体而言该领域……"这类综述句
5. D 与 E 必须分开：数字缺前提 → E；判 D 必须有正面证据，「我没看到出处」≠「没有出处」
6. expand 前先声明清单（编号 + 想确认什么）再执行；每条展开附引句；数量不限但清单必须可见
7. **没读到不等于没问题**：对某条只能说"未覆盖"，不能说"已确认无问题"，除非给出原文依据。
   这条是为了防一个错觉——"子智能体没提问题"往往只是它没读到，而不是真的干净。
8. **本存档无法核实 ≠ 不存在**：主轨的结论可能来自另一个来源（换了搜索引擎、上一轮对话、别的存档）。
   你只看得见手上这一份，找不到依据时只能说「本存档无法核实」，**不能判「主轨编造 / 该数据不存在」**。
   （实测踩过：主轨的数字来自另一个引擎的批次，子智能体判其"不存在"，实际是它视野只有一半。）

【收尾】
- 完整答复写入 {archive 去掉 .json}.notes.md，顶部 5 行 header：时间 / query / 触发理由 / 模型 / 读了多少条
- 回传给主轨只要：各段最关键一句 + 建议 expand 的编号 + 一行「已写入 <绝对路径>」
- 最多 {max_rounds} 轮，到轮必须给结论

【工具顺带反馈】
执行命令时留意 dump.py / search.py 本身有没有别扭的地方——报错、缺参数、输出难读、
字段不够用、想做的操作做不了。**单独列一节写，不要混进上面的证据状态。**
这一节不影响你的结论质量，但能帮主轨改进工具；没有就写"无"。
```

> `{dump_py}` / `{search_py}` 在派发时由主轨填入**自己刚执行过的那个绝对路径**，不在本文件写死——技能搬家后路径会变，写死必然过期。

## 每一块为什么必须留

| 块 | 保留理由 | 删掉会怎样 |
|---|---|---|
| 任务写成「回答」，不写成「审计」 | 它做的本来就是同一件调研任务，只是样本多 5 倍；写成"找错"它会为挑刺而挑刺、刻意回避一致结论 | 回传变成抬杠清单，有用的结论反而不敢说 |
| 输出分「答案 / 证据状态」 | 答案区允许它下结论，证据区负责可核性；混成一段两头不到位 | 要么只有结论无法核，要么只有素材没结论 |
| 传用户真实意图 | 不说它不知道什么重要，会把注意力平均分给 50 条 | 它重点分析偏题条目 |
| 传主轨结论 | 不传它无从判断"什么算增量"，必然把主轨说过的再讲一遍 | 重叠产出，白派一次 |
| 禁止 Read 整个 JSON | 50 条含完整 summary 的存档可达数百 KB，Read 一次就烧光它的上下文 | 它读两页就报"上下文不足" |
| 数据用 dump.py 而非长命令 | 字段白名单只在一处定义，指令里不必重复七个字段名 | 字段调整要同步改多处，必然漂移 |
| D / E 分离 | snippet 截断与源头无依据在表面上完全一样，混在一起就是误判 | 误伤率居高不下 |
| B 用三列表格（主张 / 引句 / 编号） | 自由文本读起来像总结，但没法跨条目比较、没法排序；三列能直接对着看 | 一条条散文式描述，看不出谁跟谁冲突 |
| 规则 7：没读到≠没问题 | "它没提问题"最容易被误读成"这批结果很干净"，实际常常是它没读到 | 把未覆盖当成已核验，隐患留到最后 |
| 规则 8：无法核实≠不存在 | 它只看得到手上这一份存档；主轨换过引擎或引用过上一轮结论时，它天然看不见 | 会把自己的视野局限判成主轨造假 |
| expand 先报清单 | 自判 + 自报，主轨才知道它把预算花在哪 | 无法判断它是否过度 expand |
| 要求原文引句 | 引句是唯一能被独立核实的东西，转述不可核 | 主轨只能选择信或不信 |
| 标置信度 | 它自己承认"仅凭 snippet 只够做结构判断"，标注能让主轨知道哪些要复核 | 所有结论看起来同等可靠 |
| 自己落盘 + 只回摘要 | 它上下文里有全部细节，写文件比主轨转录省一倍 | 主轨要把全文再输出一遍 |
| 停止条件 | 无停止条件时它会不断换说法重搜 | 轮次失控 |
| 工具顺带反馈（独立成节） | 它是最真实的使用者，脚本的别扭之处只有跑的人知道；独立成节是为了不污染证据报告 | 工具问题永远只有主轨自己踩 |

**已砍掉一项，不要加回来**：「主题分布 / 聚类」。主轨读 10 条也能大致知道分几类，而这最容易退化成领域综述，对核心问题无贡献。（2026-11-03 的实验里它产出过 5 类聚类，是当时最不值钱的部分。）

## 已知失败模式与对策

| 失败模式 | 实测表现 | 对策 |
|---|---|---|
| 把"前提被截断"误判为"数据无出处" | 将 ICLR 2026 的 WideSearch 基准（200 道人工题、五阶段质控）判为"样本量未知" | D/E 分离 + 必须给正面证据 |
| 复述主轨已有结论 | 首轮未传主轨结论时发生 | 把主轨结论写进 prompt 并明令禁止复述 |
| 忽略查询构造问题 | 把"召回泛化"归因为"snippet 被截断"，因为没给 query | 传原始 query 与改写后的 query |
| 综述化倾向 | 输出"该领域正处于转型期"这类无信息句 | 明令禁止 |
| 过度 expand | 拿到 expand 权限后想把半数条目都展开 | 先报清单，清单可见即可拦 |
| 把"没提到"当成"没问题" | 报告里没提某几条，主轨容易默认它们干净 | 规则 7 + 对未覆盖条目显式标「未覆盖」 |

## 参考值

以下为 2026-11-03 单次实测，仅用于判断量级，**不要当成固定参数写进任何地方**：

| 项 | 数值 |
|---|---|
| 50 条 snippet 进子轨上下文 | 约 1.6 万字符 |
| 回传主轨（只给摘要时） | 约 900 字 |
| 压缩比 | 约 18:1 |
| 展开 5 条 summary | 约 +1.2 万字符（进子轨，不进主轨） |
| 一次 expand 的额外轮次 | 1 轮 |
| 50 条 summary 全读 | 约 12.5 万字符 —— **不可行**，会撑爆 |
